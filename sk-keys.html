keys.sk

Crate key handouts for staff. Three commands sitting on top of KyronCrates so nobody running an event has to remember what a crate is called internally.

Skript3 commandsaudit logneeds KyronCrates

What it does

CommandWhoWhat it does
/givekey <crate> [player] [amount]staffHands keys to one player. Leave the player off and they go to you
/keyall <crate> [amount]staffGives everyone currently online a key, and announces it in chat
/keyseveryoneLists the crates that exist and how to open one

Staff type a plain word — kyron, netherite — and the script translates it to the crate id the plugin actually uses. Both mappings live in a block at the top of the file alongside the crate's display name, so adding a fourth crate is a short edit in one place rather than a search through the body of the script.

Decisions

It refuses to make a key itself

This is the whole reason the script is worth talking about. It would have been easier to build the key item here — name it, colour it, hand it over. It doesn't. It asks KyronCrates to do it and passes on the result.

A key is only valid because of the tag the plugin writes inside it. If this script minted its own, there would be two separate definitions of what a key is, sitting in two files that nobody would think to keep in sync. The day the plugin's format changed, staff would start handing out keys that look perfect in the inventory and open nothing — and the reports would come in as "crates are broken", not "the script is out of date".

Going through the plugin means there is exactly one answer to what a key is, and this file stays a convenience layer that physically cannot drift out of sync with it.

Getting it wrong tells you what's right

Run /givekey with nothing after it and you don't get a usage string — you get the list of crates you can actually name, each with its display name next to it. Name a crate that doesn't exist and the error lists the valid ones rather than just saying no.

That's built around the real failure case. Staff don't mistype these because they don't know the command; they mistype them because they're half-remembering whether it's nether or netherite. Answering that question inside the error is faster than making someone go and look.

The amount is optional and defaults to one, and anything below one is pulled back up to one, so a typo hands out a key instead of silently doing nothing. Console has to name a player, since there's no sensible default when there's nobody running the command.

Every handout is written down

Both admin commands are permission-gated, and both append a line to their own log file recording who ran it, who received, which crate and how many. /keyall also broadcasts to the server, so a mass handout is public by default.

Free loot is the thing staff end up accused of afterwards — who got keys, who didn't, who gave themselves a stack during an event. Chat scrollback doesn't survive a restart and nobody screenshots the moment it matters. A log file does, and it costs one line per command to keep.
