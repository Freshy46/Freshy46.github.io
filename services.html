Questions I get asked

Do I get the source code?

Yes, on request. You paid for it. Some clients only ever want the jar and the config, which is fine, but the source is yours if you want it and I won't hold it back as leverage.

What if it breaks after you've delivered it?

If it's a bug in what I built, I fix it. That isn't a support contract with a time limit on it — it's just that shipping something broken and walking away isn't delivering.

New features, or making it work on a version that came out later, are new work. The line is simple: if it never did what we agreed, that's mine. If you want it to do something else, that's a new job.

How many revisions do I get?

There's no counter. Iteration is step four of how I work and it's the part that decides whether the thing is good, so I'm not going to charge you per opinion.

What does change the price is scope. Rebalancing an ability ten times is iteration. Deciding halfway through that it also needs a GUI and a database is a different plugin, and I'll say so before doing it rather than after.

Can you work with a plugin I already have?

Usually. Building on top of another plugin's API is normal — the Skript tooling on this site drives KyronCrates through its own commands rather than reimplementing it, which is exactly this.

What I can't promise is modifying a paid plugin I don't have the source to. Tell me what you're running and I'll tell you honestly whether it's possible.

What do you need from me to start?

Your server software and version, roughly how many players it needs to hold, and a description of what the feature should feel like to the person using it. Not a spec — I'd rather hear "crates should feel like opening something, not clicking a chest" than a list of methods.

If you have a competing plugin you like parts of, say which parts. That's usually the fastest way to understand what you actually want.

Will it slow my server down?

It shouldn't, and that's a design constraint rather than an afterthought. Things that run on every block break or every tick get treated differently from things that run when someone types a command — Fresh's Sus and Crysgear both explain where that mattered and what it cost.

If you're already running badly before I start, I'll tell you that too. A new plugin isn't going to fix an overloaded server.

What it costs

I quote per job rather than publishing a rate card, because a rate card is wrong for almost every job. A one-command script and a system like AegisStaff aren't the same work and shouldn't cost the same. Tell me what you want and you get a number before anything starts — no hourly meter running, no bill that grows while you're not looking.

What moves the price, roughly in order of how much it matters:

WhatWhy it changes the price
SizeOne command that prints something is an evening. A system with its own database, GUIs and forty commands is not
StateAnything that has to remember something between restarts needs storage designing, and storage is where the hard bugs live
Custom itemsCustom models, textures or a resource pack is a separate piece of work from the plugin that uses it
InterfacesAn in-game editor is far more work than a config file, and far better to use. Worth it for anything an admin touches often
HostilityAn FFA or anarchy server needs dupe-resistance and crash-safety that a private SMP genuinely doesn't
IterationA fixed spec is cheaper than "build it and we'll see". Both are fine — say which you want

If the answer is that an existing free plugin already does what you need, I'll tell you that instead of quoting. It costs me a job and saves you money, and you'll come back for the thing that genuinely doesn't exist yet.
