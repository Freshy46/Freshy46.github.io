JARVIS

A voice assistant I built and gave a real interface to. You talk to it, it talks back, and it can actually do things — read and write files, search the web, take notes, work through a study plan or a schedule. Seventy-five tools behind one conversation.

What it does

It listens, it answers out loud, and it remembers. Speech goes in, the language model decides whether it needs a tool to answer properly, and the reply comes back as synthesised voice as well as on screen. Memory persists across sessions, so it holds context from things you told it days ago rather than starting cold every time.

The row along the bottom switches what it's set up to do. Each mode changes what it has access to and how it behaves, rather than just filtering a menu:

ModeWhat it's for
STUDYWorking through material — explanations, questioning you back, tracking what you've covered
PLANNINGSchedules, task breakdowns, working out the order things need to happen in
SYSTEMThe machine it's running on — diagnostics, resource use, the state on the side panels
WEBSearching and pulling in things it doesn't already know
FILESReading and writing on disk
NOTESCapturing things mid-conversation without breaking out of it
CHATPlain conversation with no particular job attached
SETTINGSVoice, model, mode and memory configuration
STANDBYDrops it to idle without shutting it down

The interface

The interface was as much of the work as the assistant behind it. A voice assistant with no screen gives you nothing to look at while it thinks, and no way to tell the difference between working, waiting and broken. So everything it's doing is on the wall.

The sphere in the middle is the assistant itself — thousands of particles that react to what it's doing, so idle, listening, thinking and speaking all look different from across the room. Around it, four groups of live readouts:

PanelShows
SYSTEM DIAGNOSTICSCore load, memory allocation, GPU thermal, uptime
NEURAL ACTIVITYSynaptic rate, GPU load, VRAM, and whether inference is idle or running
VOICE PROCESSINGLive input waveform, signal strength, and recognition state
NETWORK TRAFFICUp and down throughput, packets per second, latency
ACTIVE MODULESLanguage model, voice synth, speech input, link, mode, encryption
ENVIRONMENTAmbient temperature, pressure, location, conditions

The status block in the corner is the one that matters day to day — mode, whether the voice is currently speaking, whether memory is on, how many tools are loaded, which model is answering, and round-trip latency. When something feels slow, that block tells you whether it's the model, the network or the speech layer without opening a log.

Decisions

Why Flash-Lite and not the biggest model available

It's a voice assistant, so the thing being optimised is the gap between you finishing a sentence and it starting to answer. Past about a second that gap stops feeling like a conversation and starts feeling like a form submission, and no amount of extra answer quality buys that back.

Flash-Lite is the cheapest, fastest tier, which is the right default for the overwhelming majority of what gets asked — a question, a reminder, a file, a lookup. The model is exposed in settings rather than hardcoded, so anything that genuinely needs more reasoning can be moved up deliberately instead of everything paying for it all the time.

Seventy-five tools behind one conversation

The assistant isn't a chat window with a search box bolted on. It has real capability — the filesystem, the web, notes, system state — and the model picks which one it needs rather than the user picking a feature first.

That's the whole design bet: you shouldn't have to know which mode a request belongs to before you make it. Modes exist to shape behaviour and narrow the tool surface when you already know what you're doing, not as a menu you have to navigate before you're allowed to ask a question.

Memory that survives the session

Memory is on by default and persists between runs, which is the difference between an assistant and a search bar. It's a toggle rather than a permanent fixture — it's on the settings panel and the status block always shows whether it's enabled — because an assistant that quietly remembers everything and never tells you is a worse thing to live with than one that forgets.
