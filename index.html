How I build things

The item is the save file. Crysgear stores an aspect, its tier and its infusion state in the item's own PersistentDataContainer rather than in a database keyed by UUID. Restart the server, move the world, hand the item to someone else — the state goes with it, because it never lived anywhere else.

Assume the server is going to crash. A crate key is only consumed once the spin has actually started, and the prize lands in the winner's inventory whether they close the menu, disconnect, or the server goes down mid-animation. Holograms are non-persistent entities respawned on chunk load, so a hard crash can't leave text floating over an empty field forever.

Admins shouldn't be editing YAML. KyronCrates has no config worth opening. You build a crate in a menu — drop items in, click the odds up and down, watch the percentages move, close it. The file on disk is an output, not an input.

Adding to it should be boring. A new Crysgear aspect is one enum constant, one handler class and one line in onEnable. The HUD, the cooldown tracker, the core GUI and /cores info all pick it up without being told.
