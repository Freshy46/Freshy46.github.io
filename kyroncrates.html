KyronCrates

Physical crates and keys for Kyron FFA. Bind a crate to any block in the world, build its loot table in a menu, and let players spin it. Built so an admin never has to open a config file and a player never loses a key they paid for.

What it does

A crate is a real block — a chest, a beacon, whatever you're looking at when you run the command. A hologram floats above it. Right-click it holding the right key and the key is consumed, the roulette spins, and the prize goes into your inventory, or onto the floor at your feet if it's full. Right-click without a key, or left-click at all, and you get the reward preview with the real odds instead of a guess.

Keys are tagged with the crate id in NBT, so a renamed lookalike opens nothing. They can't be placed as blocks. They drop on death like any other item — which is the entire point on an FFA server, where a key in someone's inventory is a reason to fight them.

Placed crate blocks can't be broken, blown up, or moved by a piston.

How it works

The editor is the config file

crates.yml exists, but nobody is meant to open it. It's an output. Everything about a crate is built in a menu instead.

The top four rows are the loot table. Pick an item up in your inventory and click an empty slot to add it as a reward, or shift-click it straight across. Click a reward with an empty cursor to remove it. A comparator toggles into odds mode, where clicking a reward raises or lowers its weight — left for +1, shift-left +10, right −1, shift-right −10 — and the live chance percentage updates on every item in the table as you go. Weights are relative, so a reward at 10 is ten times as likely as one at 1, and you never have to make them add up to anything.

Next to the name tag is the key slot. Drop any item in there and it becomes this crate's key, keeping its name, lore and enchants. Leave it alone and it uses the default. There's a toggle for whether a win from this crate broadcasts to the server.

Closing the menu saves. So does a plugin disable while the editor is open, which is a two-line guard that stops a server restart eating twenty minutes of loot-table work.

Every slot in that menu holds a copy. Nothing ever leaves or enters your real inventory while you're editing. That isn't a detail — it's the whole reason the editor can exist. An admin menu that moves live item stacks around is a dupe waiting to be found, and on an FFA server it will be found.

The spin is theatre — the winner is already decided

The prize is rolled from the weighted table before the menu even opens. The animation is handed that result and its only job is to arrive at it convincingly.

It's a 27-slot inventory with a nine-slot strip across the middle row. Every step shifts the strip one slot left and feeds a new random reward in at the right-hand end. The real prize is inserted at exactly the step that leaves it coasting into the centre slot on the final shift. The gap between steps stretches as it goes — one tick, then two, then four, seven, eleven — so it slows into place rather than stopping dead.

step   0-19   20-29   30-35   36-39   40+
delay  1t     2t      4t      7t      11t

Because the outcome is fixed up front, the animation is disposable. It can be cut short at any frame — by a close, a disconnect, or the server going down — without changing what the player wins or leaving the outcome undecided.

A consumed key is never left unpaid

The key is taken from the player's hand only once the spin has actually started, so a failed open — wrong key, unknown crate, no rewards configured — costs nothing.

From that moment the plugin owes them a prize, and there are three ways the spin can end: it finishes normally, the menu closes, or the plugin disables underneath it. All three route into the same award() method, which guards on a flag so it can be called from anywhere, more than once, in any order. Whichever path gets there first pays out; the rest do nothing.

If the inventory is full the prize drops at the player's feet rather than vanishing. The win message uses the reward's real display name where it has one and falls back to the item's translation key where it doesn't, so it reads correctly in whatever language the client is set to. Broadcasts are per-crate, so a common crate doesn't spam chat.

Holograms that can't be orphaned

Floating crate text is the classic way to leave permanent litter in a world. Entities get saved into the chunk, the plugin gets removed or crashes before it can clean up, and the text stays there forever with nothing left that knows how to delete it.

These are non-persistent display entities. They're never written to the region file at all — they're spawned when the chunk loads and destroyed on disable. A hard crash leaves nothing behind, because there was never anything on disk to leave. Remove the plugin entirely and the world is clean the moment it next loads.

Install

Drop the jar in plugins/ and restart. Config is written by the editor, so there's nothing to set up first. Rebuild after code changes with bash build.sh.
